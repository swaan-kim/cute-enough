# 사진 준비·QA 추가 점검과 AIT 후보 — 2026-09-13

## 이번에 확인하고 고친 것

| 발견한 문제 | 수정과 확인 |
| --- | --- |
| 네트워크·이미지 디코딩 실패가 브라우저의 영문 오류로 노출됨 | 한국어 재시도 안내로 통일. 12초 시간 초과와 실제 화면 이탈을 구분 |
| 내 사진 주소 발급 실패 전에 방문 기록이 저장됨 | 서명 URL 발급 성공 뒤 방문 기록 저장. 실제 Edge 처리기에서 실패 → 재시도 → 하루 기록 한 건을 검사 |
| 미리 준비하는 도중 사진·권한이 바뀔 가능성 | 수집 권한 철회, 소유자 변경, 사진 비활성화, 최종 사진 ID·경로 불일치 차단 회귀 추가 |
| 소스만 수정하고 이전 AIT를 전달할 가능성 | production AIT 내부의 `photoPrepare`와 새 오류 안내, 기존 SVG·사진 추가·광고 연결 코드를 검사 |

내 사진·이미 모은 사진은 간식을 먹고 쓰다듬기 단계에 들어서면 준비한다. 새 사진은 세 번째 유효 입력 직후 요청해 마지막 450ms 반응과 겹친다. 간식·3회 교감·마지막 반응을 생략하지 않는다.

사전 준비는 티켓·수집·방문 기록을 만들지 않는다. 최종 요청에서 다시 확인한 사진 ID와 준비본이 같을 때만 재사용한다. 새 사진의 티켓·수집 확정 이후 이미지 다운로드가 실패할 수 있으며, 재시도는 기존 수집 권한 또는 같은 요청 ID를 사용해 중복 차감을 막는다.

## 재실행한 검증

`npm run test:flows` 전체 통과. 실패를 자동 재시도로 숨기지 않았다.

| 수준 | 결과 |
| --- | --- |
| 실제 SQL/RPC · 격리 PGlite | 158개 통과 |
| 로컬 검수 HTTP·AIT 보관·설정 | 72개 통과 |
| 실제 Edge 처리기 · 외부 통신 대역 | 2개 / 12단계 통과 |
| UI·로직 · Vitest | 101개 파일 / 1,074개 통과 |
| 앱·브라우저 타입 검사 | 통과 |
| 정상 앱 모바일 E2E | 360×640·390×844·430×844, 27개 통과 |
| 개발 React StrictMode 첫 진입·새로고침 | 1개 통과 |

정상 E2E는 무료 2회 → 0장 → 광고 보상 → 교감 → 사진, 보상 취소·중복 콜백, 준비 중 이탈, 느린 사진을 확인한다. A/B 브라우저에서는 이미 승인된 테스트 강아지로 수집·좋아요·재접속과 등록자 집계 0 → 1 → 0을 확인한다. 등록·검수·사진 추가 승인은 별도의 SQL/HTTP 검사다.

실제 광고 재고·네이티브 UI·푸시 도착·운영 다중 연결 경쟁은 이 결과에 포함되지 않는다. 기존 사용자 사진·티켓·앨범·좋아요·승인 기록을 초기화하지 않았으며 실제 광고나 알림도 보내지 않았다.

- 최근 앱에 필요한 SVG 공통 렌더러, 앨범·사진 추가 등록, 광고 복구, 사진 준비와 공용 타입·API 의존성을 함께 보관한다.
- 앱·검수·서버 테스트, 격리 QA 실행기와 AIT 단일 보관 빌드 도구를 함께 보관한다.
- 개별 검수 초안, 운영 통계·캠페인 스냅샷, 비밀 환경 파일·인증서, AIT와 테스트 결과물은 이번 커밋에서 제외한다.
- 기존 마이그레이션은 내용·이력을 보존한다. `supabase/rollout/retire-png-after-svg.sql`은 테스트가 참조하는 수동 전환 후보이며 이번 작업에서 실행하지 않는다.

## 후보와 운영 반영은 별도

후보는 공통 빌드 잠금과 입력 변경 검사를 사용하는 `npm run build:production`으로만 만든다. 전달 위치는 `AIT/LATEST/cute-enough.ait`이며 `AIT/LATEST/release.json`의 소스 커밋·입력 fingerprint·runtime·광고 플래그·deploymentId·SHA-256·바이트 수로 식별한다. `npm run ait:check`와 실제 AIT 내용 검사를 통과한 파일만 전달한다. 과거 후보를 임의로 복사하거나 테스트 파일을 LATEST로 승격하지 않는다.

사진 준비의 서버 반영 순서는 다음과 같다.

1. 운영 마이그레이션 이력에서 `20260912000100_photo_prepare_rate_limit.sql` 적용 여부 확인 및 필요한 후속 적용
2. 해당 허용 목록과 호환되는 `pet-api` 배포
3. 새 AIT의 Toss QR로 내 사진·재열람·새 수집·광고·재시도 확인

이번 요청은 점검·소스 푸시·AIT 파일 생성이다. 운영 DB 적용, Edge 재배포, 토스 번들 업로드, 푸시·광고 스위치 변경, 개별 강아지 공개 확정, 출시를 포함하지 않는다. 서버가 아직 `photoPrepare`를 지원하지 않으면 사전 준비 실패는 무시하고 기존 최종 사진 요청으로 이어진다.
