# 검수 SVG 디자인 저장과 전환

## 구현 계약

사용자 요청은 제출값으로 보관합니다. 제작자가 검수한 실제 도형은 PetDesignV1(schemaVersion 1, motionVersion 1, viewBox, ordered nodes)로 저장합니다. 공개 화면은 편집 설정 대신 확정 도형만 렌더합니다. tail/tongue 동작 그룹은 저장된 부모 변환 내부에 유지하고 공용 CSS가 기존 동작을 수행합니다.

허용한 SVG 요소와 속성만 통과합니다. 마스크·클립·그라데이션 ID는 저장 시 정규화하고 렌더 시 인스턴스 접두어를 붙입니다. SHA-256은 정렬된 키와 정규화 문서로 계산하며 DB와 TypeScript 규칙을 함께 검사합니다.

비공개 editorState는 최종 traits/style/accessory와 compiler input, baseDocument, document를 보관합니다. 재편집 시 변경하지 않은 도형만 새 설정을 따르고 수동 변형과 추가 도형은 보존합니다. 공개 payload에는 editorState와 검수 메모가 없습니다.

## 저장

- POST /api/review-design-draft → save_pet_design_draft: 예상 초안 revision과 공개 버전을 검사하고 초안 저장. 즉시 DB 재조회와 SHA 비교.
- POST /api/review → review_pet_submission_with_design: 저장한 초안을 명시적으로 승인하거나 등록 반려.
- POST /api/review-publication → manage_pet_publication_with_design: 보정 공개·재공개 또는 중지.
- 확정 RPC는 버전 검사, 변경 불가능한 확정 버전 생성, pets 참조·승인 상태·최종 메타데이터·감사 기록을 단일 트랜잭션으로 처리.
- 일반 사용자 요청의 제작자 필드를 거부. 일반 사용자에게 draft/version 쓰기나 검수 RPC 실행 권한 없음.
- 새 앱은 designFormat: svg-scene-v1 전달. 집·교감·공유·내 강아지·앨범에 현재 공개 참조를 조회하고 검증한 publishedDesign 전달.
- 문서가 없거나 미지원이면 재시도. 다른 강아지 생성이나 PNG fallback 없음. 디자인 재조회는 사진 열람권을 쓰지 않음.

## 비교

| 방식 | 장점 | 단점 |
|---|---|---|
| 설정 + ID별 SVG 재생성 | 데이터 작음, 기존 동작 용이 | 검수와 앱의 코드 차이로 외형 누락, 새 소품마다 배포 필요 |
| PNG 확정 | 저장한 픽셀과 외형 일치 | 부위별 애니메이션 불가, 해상도·스토리지·서명 URL 관리 필요 |
| 확정 SVG 도형 | 검수 외형·레이어 보존, 기존 동작 유지, 새 도형 저장만으로 반영 | 문서와 버전 저장량 증가, 검증·편집 병합이 복잡, 새 스키마·동작 추가 때 배포 필요 |

렌더러/CSS 변경은 기존 도형의 표시에도 영향을 줄 수 있으므로 motionVersion 1 호환성을 유지합니다. 확정 도형 자체는 변경 불가이며 수정은 새 보정 버전으로 남깁니다.

## 배포 및 제거 조건

1. 운영 상태·사진 수·공개 버전·감사 기록을 조회해 기준선을 남깁니다. 003 additive migration만 정확히 적용하고 개별 승인 상태는 변경하지 않습니다.
2. 현재 검수 특수 도형을 전환 초안으로 준비합니다. 기존 승인견은 제작자가 최종 확인한 문서만 전환합니다. 대기견 자동 승인 금지.
3. SVG 지원 API와 AIT를 테스트합니다. 새 앱에서 SVG 없는 승인견은 재시도로 표시되므로, 확인이 끝난 공개 집합의 전환과 앱 활성화를 함께 수행해야 합니다.
4. 호환 기간에는 기존 운영 앱을 유지합니다. 새 앱·데이터 전환 확인 뒤 PET_REQUIRE_SVG_DESIGN=true로 구형 클라이언트의 426 CLIENT_RESTART_REQUIRED 안내를 켭니다. 새 앱 재실행 경로를 실제로 확인합니다.
5. 쿠키 머리·귀·턱, 설기 선글라스+나비넥타이, 치즈 삼각 치즈, 구르미 스카프+솜사탕과 전체 공개견을 기준 자세·모션·여러 인스턴스로 확인합니다. 새 도형을 저장하고 동일한 앱 번들에서 재조회해 표시되는지 검사합니다.
6. 모든 공개 참조 전환과 사용자 화면 검증 이후 PNG 호환 API·파일과 구 렌더 경로를 제거합니다. `supabase/rollout/retire-png-after-svg.sql`은 실행 전제 검사를 포함한 후보입니다. 실행 시 후속 migration으로 남기고 적용한 기존 migration은 지우지 않습니다.
7. pet-artwork 파일은 운영 참조가 없음을 확인한 뒤 Storage API로 정리하고 빈 전용 버킷을 삭제합니다. pet-photos, pet_photos, 구르미 사진 3장, 앨범·수집·승인 감사 기록은 유지합니다.

## 완료 판정

로컬 구현·테스트, 운영 적용, AIT 배포, 제작자 공개 확정, PNG 최종 철거는 각각 별도 단계입니다. 확인받지 않은 검수본을 과거 승인 이력만으로 공개하지 않습니다. PNG 호환 코드가 남아 있으면 전체 전환 완료라고 표시하지 않습니다.
