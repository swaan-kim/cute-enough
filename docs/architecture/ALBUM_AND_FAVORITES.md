# 강아지 티켓 · 강아지 앨범 · 하루 한 장

사진을 한 번 수집하면 해당 **사진 ID**의 권한을 서버에 저장합니다. 모은 사진은 날짜·티켓 충전 시각과 관계없이 무료입니다. 신규 수집은 사용자·강아지별 KST 하루 한 장이며, 사진 공개 성공 시에만 티켓 1장을 씁니다. 무료 티켓 최대 2장·3시간 충전과 공개견 4마리 + 내 최신 강아지 1마리 정책은 유지합니다.

## 사용자 흐름

홈의 `강아지 앨범` → `모든 친구 / 마음에 담은 친구` → 캐릭터 카드 → 모은 사진 넘겨보기. 목록에는 실사를 내려받지 않고 캐릭터와 사진 수만 보여줍니다. 사진창의 기존 잘림·저장·이름표·공유·하트 효과는 유지합니다.

`♡ 또 보고 싶어요`를 선택하면 `♥ 마음에 담았어요`로 바뀝니다. 사용자·강아지별 최대 1개이며 다시 선택하면 해제합니다. 사진 터치 애니메이션은 집계하지 않습니다. 업로더는 `내가 소개한 강아지`에서 `마음에 담은 사람 N명`을 확인합니다. 기존 하트와 업로드 기록을 재생성하거나 지우지 않습니다.

집에서는 모든 강아지를 **선택 → 간식 → 쓰다듬기 → 사진** 순서로 만납니다. 앨범과 내가 소개한 강아지 목록에서만 바로 사진을 엽니다. 추가 사진 구매 버튼이나 별도 직행 흐름은 없습니다.

| 상태 | 교감 뒤 사진 | 차감 |
| --- | --- | --- |
| 첫 공개 / 다른 날짜에 오늘 집에 재배정 | 순서상 안 본 다음 사진 | 1장 |
| 오늘 이미 신규 수집 | 오늘 수집한 같은 사진 | 없음 |
| 모두 수집 | 보유 사진 순환, 가능한 한 직전 반복 제외 | 없음 |
| 티켓 없음·보유 사진 있음 | 보유 사진 | 없음 |
| 내 pending/approved | 소유자 실사 | 없음 |
| 타인 pending | 캐릭터만, 실사 URL 미제공 | 없음 |

놀이를 시작할 때 `collect/replay` 의도를 고정합니다. 무료 놀이 중 충전돼도 유료로 바꾸지 않습니다. 공유 첫 만남은 첫 사진을 수집할 수 있지만, 이미 만난 친구의 공유 링크에서는 보유 사진만 무료로 엽니다. 다음 날 그 친구가 반드시 집에 온다고 약속하지 않습니다.

## 사진 설명 수정

Supabase Dashboard → Table Editor → **pet_photos** → 해당 **사진 ID** 행의 `caption`을 수정합니다. 비워 두면 설명 없이 `모은 사진 1/3`만 표시합니다. 예: `꾸벅꾸벅 졸고 있는 구르미`.

- 선택 항목, 일반 텍스트 최대 30자. HTML·제어문자는 허용하지 않습니다.
- 강아지 ID가 아니라 사진 ID별 저장이며 새 사진 조회부터 최신값을 표시합니다.
- 사진 ID·Storage 경로·수집 권한·티켓은 변경하지 마세요. 설명은 저장 이미지의 워터마크에 추가되지 않습니다.
- 모은 수/활성 공개 사진 수와 앨범 페이지 `사진 1/2`는 별개입니다. 소유자는 수집 제한 없이 설명만 봅니다.

## 권한과 호환성

- `user_photo_unlocks`: 사용자·사진별 영구 권한. 공개 중지·삭제·비활성 사진의 접근을 계속 허용한다는 의미는 아닙니다.
- `pet_favorites`: 마음에 담기 집계의 단일 원본. 해제해도 앨범은 사라지지 않습니다.
- `pet_photo_reveal_requests`: 요청 ID별 사진과 차감 결과를 고정해 통신 재시도·중복 요청으로 추가 차감되지 않게 합니다.
- 새 클라이언트는 기존 `apiVersion: 2`와 **albumVersion: 2**, 사진 요청에는 `photoIntent: collect | replay`를 함께 보냅니다. 구버전 albumVersion 1도 하루 한 장을 우회할 수 없습니다. 당일 중복은 같은 사진을 무료 반환합니다.
- `collection`은 활성 공개 사진 수·모은 수·오늘 수집 여부·신규 수집 가능 여부입니다. 사진 응답에 선택적 `photoCaption`이 추가됩니다. 미수집 URL·Storage 경로는 반환하지 않습니다.
- 실사 URL은 필요할 때만 권한 확인 후 10분짜리 서명 URL로 제공합니다. URL·실사 원본을 영구 브라우저 저장소에 저장하지 않습니다.
- 사진 파일을 교체할 때는 **새 Storage 경로와 새 사진 ID**를 사용합니다. 기존 사진 ID 또는 경로의 내용 덮어쓰기는 이전 이용자의 권한을 새 사진에 잘못 연결할 수 있으므로 금지합니다.

이전 공개 기록에는 사진 ID가 없어 정확한 과거 사진 복원이 불가능합니다. 이번 마이그레이션은 기존 만남 기록이 있는 승인견마다 현재 대표 사진 1장을 `legacy_gift`로 제공합니다. 기존 업로드·검수 기록은 삭제하지 않습니다. 배포 시 한 번 이관하고, 사용자가 새 클라이언트를 처음 사용할 때 구버전에서 추가로 만난 기록을 한 번만 보충합니다. 별도 이관 영수증을 남겨 철회·삭제된 사진을 다른 사진으로 재선물하지 않으며, 새 클라이언트에서 공개한 사진은 정확한 사진 ID의 `reveal` 기록으로 구분합니다.

## 운영 확인

1. 새 SQL 마이그레이션과 기존 운영 이력을 확인하고 **새 마이그레이션만** 트랜잭션으로 적용합니다. 이력에 없는 예전 개별 강아지 보정 SQL을 일괄 재실행하지 않습니다.
2. `pet-api`를 배포하고 production `.ait`를 생성합니다.
3. Toss QR 사용자 A가 타인의 사진을 수집하고 마음에 담습니다. 앨범에서는 즉시 재열람, 집에서는 다시 간식·쓰다듬기 뒤 무료 재열람이어야 합니다.
4. 업로더 B가 `내가 소개한 강아지`를 다시 열어 마음에 담은 사람 1명이 늘었는지 확인합니다. A가 해제하면 1명이 줄어야 합니다.
5. 자정·3시간 충전·동시 요청·통신 재시도에도 하루 한 장 및 단일 차감을 확인합니다. 사진 caption 수정 후 재조회, 다른 사진으로 넘길 때 설명 분리를 확인합니다.
6. 드롭한 자리에서 1.5초 쉬고 산책하는지, 놀이 왕복 후 좌표 유지·방 8px 경계·취소 시 사진 미선택을 확인합니다.

일반 테스트는 `npm test`, 타입 검사는 `npm run typecheck`, 번들은 `npm run build:production`입니다. 실제 Postgres 동작을 검증하는 SQL 테스트는 `PGLITE_MODULE_PATH`에 설치된 `@electric-sql/pglite`의 모듈 경로를 지정한 뒤 `node --test supabase/migrations/photo-album-and-favorites.node-test.mjs`로 실행합니다. PGlite는 앱 운영 의존성이 아닙니다.

앨범은 페이지당 기본 20마리이며 마음에 담은 친구 필터와 키셋 페이지 이동을 지원합니다. 메타데이터는 세션 메모리에서 최대 5분 재사용하고 공개·하트 변경 시 무효화합니다. 실사·서명 URL·캡션은 사진 조회마다 권한 확인 후 읽습니다. 실시간 구독·좋아요별 폴링·별도 AI API는 사용하지 않습니다.
