# 사용자 화면과 서버의 책임

현재 소스 기준의 흐름입니다. [과거 구현 기록](../history/UPLOAD_REVIEW_SHARE_FLOW.md)에 있는 구형 승인 RPC와 시간제 재열람 정책은 현재 절차가 아닙니다.

| 흐름 | 프런트엔드 | 서버·DB가 확정하는 것 |
| --- | --- | --- |
| 첫 집 진입 | 공개 4마리 + 내 최신 강아지 최대 1마리, 티켓 카드 | 익명 사용자 확인, KST 날짜별 고정 슬롯, 최대 2장·3시간 충전 |
| 등록 | 사진 1~5장, 필수 이름 1~4자, 기본 모습·선택 꾸미기 | 요청 ID별 단일 등록, 비공개 원본 저장, 소유권·용량 검사 |
| 제작자 검수 | localhost에서 초안 편집·사진 관리 후 명시적 확정 | 불변 SVG 버전·정규화 해시·공개 참조·상태·감사 기록 |
| 집에서 사진 만나기 | 간식 → 쓰다듬기/터치 3회 → 사진 | 두 번째 입력부터 기존 API로 권한 확인·서명·원자적 수집/차감 |
| 티켓 0장 | 간식 행동으로 광고를 열기 전 짧은 안내, 취소 시 같은 간식 유지 | 완료 보상만 확정, 중복 콜백·요청은 1회 처리, 자연 충전 시간 유지 |
| 앨범·내 강아지 | 사진창부터 열고 로딩·재시도, 재조회 실패 시 기존 목록 유지 | 모은 정확한 사진 또는 소유자 사진만 URL 제공 |
| 추가 사진 | 내 목록에서 최대 허용 수까지 접수 | 기존 사진·SVG·수집권 불변, 추가 사진만 별도 검수 |
| 마음에 담기 | 사진창 버튼, 업로더 목록의 사람 수 | 사용자·강아지당 1개, 멱등 설정/해제, 사진 수집과 분리 |

## 검수 외형은 저장 문서 그대로

사용자가 고른 요청값은 원본으로 보존합니다. 제작자는 비공개 초안에서 최종 외형을 결정하고, `review_pet_submission_with_design` 또는 `manage_pet_publication_with_design`으로 확정합니다. 앱은 `PetDesignV1`을 공용 `PetDesignSvg`로 표시합니다. ID별 외형 재생성이나 PNG 대체는 하지 않습니다. 누락·미지원·해시 불일치는 해당 디자인 재시도로 표시합니다.

검수 중인 사진은 소유자만 열 수 있고 타인에게는 캐릭터만 전달합니다. 승인 후 공유·내 목록은 다음 조회부터 최종 문서를 표시하며, 새 공개견의 다른 사용자 집 편입은 다음 KST 날짜 후보부터입니다. 초안 저장·미리보기는 공개 확정이 아닙니다.

## 사진·티켓·요청의 경계

사진 파일은 미리 다운받더라도 세 번째 입력과 마지막 900ms 반응이 끝난 뒤 보여줍니다. 두 번째 입력에서 서버가 확정한 수집은 중간 이탈해도 보존합니다. 같은 요청 ID로 결과를 복구하고, 늦은 응답은 떠난 사진창을 다시 열지 않습니다.

서버의 5xx나 전송 중 취소는 처리 결과가 불명확할 수 있습니다. 클라이언트는 명확한 사전 거절과 구분해 등록 내용을 임의로 새 요청으로 바꾸지 않습니다. 외부 취소 리스너·타이머는 요청 완료 후 정리하고, 집 조회는 요청 세대가 지난 응답을 적용하지 않습니다.

`user_photo_unlocks`는 정확한 `photo_id + pet_id`를 참조합니다. 정상 검수는 사진을 비활성화할 뿐 수집권을 지우지 않습니다. 후속 무결성 마이그레이션은 참조 중인 사진 행 삭제를 거절하고, 기존 잘못된 연결을 발견하면 전체 적용을 실패시킵니다. 자동 삭제·자동 재배정은 하지 않습니다.

신규 수집은 사용자·강아지별 하루 한 장이며 모은 사진의 재열람은 무료입니다. 자세한 규칙은 [앨범 설계](ALBUM_AND_FAVORITES.md)를 따릅니다.
