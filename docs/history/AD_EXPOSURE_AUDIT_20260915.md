> 아래 내용은 34~36번 점검 이력이다. 이후 사용자가 요청한 **간식 주기 → 확인창 없이 광고 표시** 변경과 최신 검증은 [직접 광고 연결 기록](DIRECT_TREAT_AD_20260915.md)을 따른다.

## 무엇이 문제였나

운영 중인 버전과 수정한 테스트 버전이 달랐다. 점검 시 일반 사용자는 `20260907-30`을 사용하고 있었고, 티켓 0장 광고 버튼·선택·복구 수정이 포함된 `20260911-31`은 아직 `REVIEWING`이었다. `20260913-33`도 테스트 등록 상태로, 출시되지 않았다. 로컬 AIT 생성이나 테스트 푸시 성공만으로 운영 앱이 바뀌지 않는다.

첨부 표의 33.33%를 광고 오류율이나 광고 재고 부족으로 해석하지 않았다. 공식 콘솔의 9월 6~14일 집계는 **광고 요청 3회 → 로드 성공 3회 → 표시 시도 1회 → 노출 1회**였다. 앱 진입·복귀와 시청 후 다음 광고를 미리 준비하므로 사용되지 않은 로드가 생길 수 있다. 집계는 버전별 원시 로그가 아니므로 두 번의 미노출 원인을 특정할 수는 없다.

## 확인한 범위

- 보상형 지면: 활성, 지면 제한 없음. 별도 제한 상태 도구는 지원되지 않아 지면 응답에 포함된 상태까지만 확인했다.
- production Edge `pet-api` v30, Edge 광고 설정과 DB 광고 설정 모두 ON.
- 최종 클라이언트: 티켓 0장 → 강아지 선택 → 간식 선택 → `광고 보고 간식 주기` → 광고 확인 → 서버 세션 생성 → 광고 표시 → `userEarnedReward` 보상 저장 → 고른 간식 자동 먹기·쓰다듬기 → 사진.
- 광고 취소·불러오기 실패·중복 콜백·불확실한 서버 요청·앱 복귀 복구를 테스트했다. 로드 완료 후 이벤트 구독 해제는 공식 SDK 사용법에 맞으므로 유지했다.
- 실제 Edge의 광고 관련 코드는 로컬과 일치했다. 아직 배포하지 않은 별도 `photoPrepare` 경로는 현재 클라이언트에서 호출하지 않으므로 이번 작업에 섞어 배포하지 않는다.
- 네 Toss Origin의 사전 요청 204, 유사 주소·null·file 스킴 403, 잘못된 익명키 401을 운영 API에 읽기 전용으로 확인했다. 광고 진단을 위해 운영 사용자의 티켓이나 기록을 변경하지 않았다. 이후 사용자가 별도로 요청한 전체 도감 초기화는 [별도 기록](ALBUM_RESET_20260915.md)에 범위와 복구 정보를 남겼다.

## 최소 개선

광고 표시를 막는 새로운 재현 결함은 발견되지 않았다. 기존에 수정한 광고 진입·복구 흐름을 유지하고, 일반 실패로 합쳐지던 진단에 **이전 보상 복구 / 서버 세션 시작 / 네이티브 광고 표시 / 보상 완료** 단계를 추가한다. 앱이 보내는 진단에 강아지·사용자·세션·요청 ID, 원본 오류 문구나 URL은 추가하지 않는다. SDK가 자체 수집하는 공통 항목과는 별개다.

무료 티켓 2장·3시간 충전·일일 광고 제한·명시적 광고 선택·시청 보상 조건은 변경하지 않는다. 광고 수치를 올리려고 자동 재생하거나 무료 재열람을 유료로 바꾸지 않는다.

## 검증 및 배포 경계

관련 단위·통합 테스트, 서버 SQL/Edge/HTTP 테스트, 전체 회귀·타입 검사, 360·390·430px 브라우저 흐름, production AIT 검증 결과를 확인하고 후보를 업로드한다. 브라우저 광고는 SDK 콜백 모형이며 실제 광고 재고·네이티브 화면 성공을 대신 증명하지 않는다.

빌드·업로드·테스트 푸시와 검토 요청·일반 사용자 출시를 구분한다. 새 번들 테스트 푸시 후 사용자 휴대폰 확인을 받으며, 검수 중인 31번은 임의 취소하지 않는다. 최종 파일·해시·기능 플래그·deploymentId는 `AIT/LATEST/release.json`, 업로드 결과는 같은 후보의 `deployment.json`에 기록한다.

## 추가 요청: 광고는 간식 단계에서

점검 중 사용자가 진입 순서를 수정했다. 티켓이 없는 새 친구도 선택하면 먼저 교감 화면을 보여주고, 간식을 골라 `광고 보고 간식 주기`를 눌렀을 때만 광고 확인으로 이어진다. 집에서 강아지를 선택하는 것만으로 광고를 열지 않는다. 클릭·키보드·드래그는 모두 같은 간식 권한 검사에 걸리며, 시청 보상을 서버에서 확인한 뒤에만 먹기와 쓰다듬기를 이어간다. 취소·오류는 선택한 간식을 유지한다.

진단만 반영한 중간 후보 `20260915-34`는 업로드됐지만 새 간식 UX를 포함하지 않는다. 최종 후보는 `20260915-35`이며, 테스트 푸시는 이 버전으로 보낸다. 도감 전체 초기화는 별도 운영 변경으로 검증·기록하며, 강아지·실사 원본 삭제와 혼동하지 않는다.

광고 준비 중 앱 종료나 같은 강아지 재진입 후 이전 비동기 요청이 늦게 광고를 여는 경합도 막았다. 요청의 강아지 ID뿐 아니라 현재 간식 권한 요청 객체와 화면 수명을 함께 확인한다. 승인 상태가 바뀌어 접근할 수 없거나 사진 권한이 확정되지 않은 경우에도 간식·사진을 먼저 진행하지 않는다.

최종 검증: 전체 회귀·타입 검사 1,103개, SQL 회귀 168개(초기화 10개 포함), HTTP/Storage 72개, 실제 Edge 테스트 2개·13단계 통과. 360·390·430px E2E 43개 통과·타이밍 비교용 2개 의도적 제외, 개발 StrictMode 1개 통과. production AIT의 deploymentId·SHA-256·실제 번들 바이트와 광고 ON/테스트 모드 OFF를 확인했다. 네이티브 광고 성공은 아래 휴대폰 확인이 남아 있다.

35번은 HTTP PUT 200과 콘솔 `CREATED`를 확인한 뒤 요청자 본인에게 테스트 푸시를 발송했다. deploymentId는 `01a0a3e0-e818-72a7-af59-50c013f451ef`, SHA-256은 `b90851bcb7a97139188bca06b3ccfdcebcad75fa685fd1de888f284da7371944`, 크기는 2,713,673바이트다. `isTested=true`는 푸시 준비 완료일 뿐 실기기 통과가 아니다. 일반 사용자 라이브는 여전히 30번이며, 31번 검수를 임의 취소하거나 35번의 검토·출시를 실행하지 않았다.

## 후속 요청: 문구 축약·공유 티켓 확인

35번 업로드 이후 요청에 따라 광고 확인 제목을 `광고를 보고 지금 이 친구 만나기`에서 `광고 보고 간식 주기`로 줄였다. 간식 화면과 확인 버튼은 기존 문구를 유지한다. 360·390·430px 광고 진입 E2E 3개와 관련 클라이언트 테스트 147개, 타입 검사·production AIT 검증을 통과했다. 후속 업로드 요청에 따라 `01a0a3f0-9dd4-7abd-ba30-26f27e1ae905`를 **20260915-36으로 업로드하고 본인 테스트 푸시를 발송했다.** 실제 AIT·LATEST·ARCHIVE의 SHA-256 `6935736ebcbf61ab6dd140bd662b4d0a8c5a933d97fb2711f95d5766d714ba72`와 크기 2,713,676바이트를 확인했다. `AIT/LATEST/deployment.json`에 업로드·푸시 결과를 기록했다. 실제 휴대폰 검증·검토 요청·일반 사용자 출시는 아직 아니다.

공유 보상은 일반 강아지 링크 공유가 아니라 `친구에게 공유하고 티켓 받기` 연락처 초대의 `sendViral` 결과로 적립한다. 운영 DB와 Edge 공유 스위치가 ON이고 모듈 ID·서비스 RPC 3개 구현도 일치했다. 서버 SQL 24개와 API/브리지 24개 테스트를 통과했다. 같은 요청·세션 내 같은 이벤트 순서의 재전송은 중복 적립하지 않고, 닫기·취소만으로 티켓을 지급하지 않는다. 보너스 티켓이 반영되면 홈 수량과 기존 선택한 강아지의 간식 권한을 갱신한다.

현재 운영에는 공유 세션 4건, 지급 이벤트·지급 수량 모두 0건, 조정 필요 0건이 있다. 이는 실기기 지급 성공을 확인한 기록이 아니다. 콘솔 공유 상세 MCP는 `등록되지 않은 요청`, 웹 콘솔은 로그인이 필요해 현재 운영 기간·친구당 수량은 재확인하지 못했다. 과거 기록의 친구당 1장을 이번에 재검증한 값처럼 안내하지 않는다. 토스 앱에서 실제 연락처 초대 성공 후 보너스 티켓 증가 확인이 남아 있다. 테스트 때문에 실제 초대 발송이나 운영 보상 지급은 하지 않았다.

## 실제 휴대폰 확인

1. 일반 서비스 아이콘 대신 이번 후보 테스트 푸시 또는 QR로 진입한다.
2. 무료·보너스 티켓이 0장이고, 아직 수집 가능한 사진이 있는 강아지에서 광고 버튼을 누른다. 이미 모은 사진 재열람은 무료라 티켓 소진 수단이 아니다.
3. 강아지 선택 → 간식 선택 → `광고 보고 간식 주기` → 광고 확인 → 실제 전면 광고 → 끝까지 시청 → 고른 간식·쓰다듬기 → 사진을 확인한다. 광고 보상은 선택한 강아지 만남 권한이며 무료 티켓 숫자가 즉시 +1 되는 방식이 아니다.
4. 취소·실패에는 보상이 없고 재시도가 가능한지 확인한다. 테스트 목적으로 운영 기록을 삭제하거나 임의 티켓을 차감하지 않는다.
