# SVG AIT·업로더 표시 보완 · 2026-09-06

> 과거 구현·배포 기록입니다. 당시 상태·명령은 현재 운영 절차가 아닙니다. [문서 안내](../README.md)에서 현재 가이드를 확인하세요. 도감 초기화·승인·출시는 별도의 명시적 확인 없이 실행하지 않습니다.

## 결론

제작자가 명시적으로 확정한 `PetDesignV1`을 **등록한 주인과 다른 사용자 모두 공용 `PetDesignSvg`로 표시**하도록 앱 연결을 보완했다. 사용자 설정이나 개별 강아지 ID로 공개 외형을 다시 만들지 않는다. 새 사용자 소품 선택지는 추가하지 않았다.

아래는 로컬 구현/검증/후보 파일 생성 결과다. 실제 강아지 공개 확정과 AIT 업로드·출시는 하지 않았다.

## 이번에 수정한 부분

- 앱 API 응답 수신 시 문서를 정규화하고 SHA-256, 문서·동작 버전, 공개 디자인 버전을 검사한다. 불일치/미지원 외형은 해당 강아지의 재시도로 격리하고 성공한 사진·티켓 응답은 버리지 않는다.
- `mine`에서 확인한 승인/보정 디자인을 홈의 내 강아지·선택한 강아지·앨범에도 동기화한다. 역으로 집/공유/앨범에서 본 최신 공개 문서도 같은 메모리 캐시에 반영한다.
- 늦게 끝난 이전 집 요청이 더 최신의 승인 버전을 덮지 못한다. `myPets` 전체 업로드 목록을 집 목록으로 대체하지 않는다. 소유권, 방 슬롯, 사진 URL, 수집 기록, 티켓을 외형 동기화로 바꾸지 않는다.
- 새 조회에서 같은 디자인 버전의 공개 중지 또는 문서 실패를 받으면 준비된 SVG 캐시도 비운다. 반면 디자인만 재시도해서 복구한 뒤 원래의 오래된 부모 요약으로 돌아왔다는 이유만으로 복구본을 지우지 않는다.
- 승인 대기 중 교감 화면에 머물러도 보이는 동안 30초 간격 또는 앱 복귀 시 상태를 확인한다. 도형 갱신으로 간식/쓰다듬기 단계를 건너뛰거나 티켓을 차감하지 않는다.
- 내 강아지 화면 복귀 시 1분 이상 지난 목록은 갱신한다. 홈 복귀 시 기존 5분 캐시 기준을 적용한다. 즉시 푸시 방식이 아니라 다음 조회/복귀/대기 상태 확인에서 반영된다.
- 서버의 `submissionStatus.result.pet`에도 공개 SVG를 전달하도록 보완했다. 승인 뒤 통신 재시도로 등록 결과를 복구할 때도 문서가 빠지지 않는다. 이 추가 서버 수정은 아직 운영에 배포하지 않았다.

## 현재 운영 상태 — 읽기 전용 확인

- `pet-api`: **25 / ACTIVE**. 앞선 SVG 기본 API는 배포되어 있다.
- 승인 **8마리**, 대기 **5마리**, 공개 SVG 참조 **0개**.
- 미전환 승인견: 구르미·하늘·우유·배추·티티·몽이·치즈·쿠키.
- 이번 작업에서 DB 적용, 초안/확정 저장, 승인, 운영 스위치 변경, Storage 정리는 실행하지 않았다.

**현재 새 SVG 앱만 배포하면 미전환 승인견은 재시도로 표시된다.** 제작자가 기존 승인견의 현재 검수본을 먼저 확인하고, 공개 데이터 전환과 새 앱 활성화를 함께 계획해야 한다. 과거 승인 이력은 현재 SVG 초안의 공개 확정을 대신하지 않는다. 구형 앱은 전환된 SVG를 재생성하지 않고 재실행 안내를 받으므로, 실제 배포/전환 순서를 별도 검증해야 한다.

## 검증

- 앱 전체 및 SVG API 테스트 **453개**, 검수/DB 테스트 **27개** 통과.
- 타입 검사, private 웹 빌드, 자산 정리, AIT 개발 도구 미포함 검사, AIT 패키징 통과.
- 주인 화면 테스트: pending → 승인 SVG → 내 강아지 → 홈 왕복, 기존 업로드 보존, 늦은 집 응답 차단, 교감 중 승인 갱신, 사진 요청/티켓 미사용 확인.
- 기존 로컬 전환 후보 13마리의 검수/앱 26개 SVG DOM은 인스턴스 ID를 정규화하면 동일했다. 꼬리 흔들기·혀 헥헥·간식 모션도 양쪽에 연결됨을 브라우저에서 확인했다.
- 360×640 로컬 샘플 모드에서 집 → 간식 → 쓰다듬기 3회 → 실사 사진 흐름을 확인했다. 이것은 운영 승인/사용자 계정을 변경하지 않는 모의 검증이다.
- **운영 DB에 실제 확정한 한 마리의 SVG가 아직 없어, 실제 업로더/타 사용자 A/B 및 Toss QR 검증은 미완료다.**

## 남은 순서

1. 제작자가 전환할 기존 승인견의 최종 SVG를 명시적으로 확인한다. 대기견은 자동 승인하지 않는다.
2. 승인된 배포 범위에서 최신 운영 API와 중첩 등록 복구 수정만 대조/반영한다.
3. 확정 저장 전 문서, DB 재조회 문서, 주인/타 사용자 API 문서의 버전·정규화 SHA를 비교한다.
4. 새 AIT QR에서 같은 문서·소품·교감 동작과 주인의 전체 업로드 기록을 검증한 뒤 운영 전환한다.
5. 전환 검증 뒤에만 기존 PNG/구 공개 경로를 후속 마이그레이션으로 철거한다. 실사, `pet-photos`, `pet_photos`, 구르미 사진 3장, 앨범·수집·감사 기록은 철거 대상이 아니다.
