# 검수 확정 이미지 점검 · 2026-09-06

## 재점검 · 검수 저장 검증 보완

- 운영 재조회: 승인견 8마리(쿠키·치즈·몽이·배추·티티·우유·구르미·하늘) 모두 `artworkStatus: missing`. 옹이·설기·밀크·이름 없는 강아지·부추는 승인 대기다. 현재 초안의 최종 저장 범위는 사용자에게 확인을 요청했다.
- 업로드한 PNG를 다시 내려받아 원본 바이트·SHA-256이 일치해야 승인/보정 RPC를 호출하도록 보완했다. 실패한 파일은 즉시 삭제하지 않는다.
- 검수 목록은 누락·정상·디자인 버전 불일치·서명 실패를 구분한다. 버전 불일치 파일은 표시하지 않고, 개별 서명 실패가 다른 목록을 막지 않는다.
- 만료된 검수 이미지 주소는 검수 목록을 다시 조회해 갱신한다. AIT 인증 API로 재시도하거나 임의 SVG로 대체하지 않는다.
- 목록에서 저장본과 확인 필요 건수를 표시하고 미리보기 크기를 확대했다. 관련 Node 테스트 28개와 검수 UI 테스트 25개, 타입 검사가 통과했으며 검수 서버를 재시작했다.
- 이번 보완으로 강아지를 승인하거나 이미지를 확정 저장하지 않았다. AIT·운영 API 갱신·DB 가드의 미배포 범위는 [AIT 연동 문서](REVIEW_ARTWORK_AIT_INTEGRATION_20260906.md)를 따른다.

## 최초 점검

### 후속 소품 초안 · 치즈 / 구르미

치즈는 기존 공을 삼각 치즈로 교체한 검수 전용 초안이며, 구르미는 기존 흰 귀·하늘색 스카프를 유지하고 구름 모양 솜사탕을 추가했다. 두 초안 모두 64·114·190px 화면 확인과 관련 테스트/타입 검사를 마쳤다. 기존 공용 렌더러·사용자 소품 선택지는 변경하지 않았다. 실제 확정 이미지 저장과 AIT 배포는 수행하지 않았다.

구르미 운영 사진 재확인 결과: 활성 사진 3장(sort_order 0/1/2)과 Storage 파일 3개가 모두 존재한다. 운영 `get_pet_album`/`get_pet_photo_collection`은 활성·Storage 존재 사진을 전체 수에 포함하므로 전체 3장 집계 대상이다. 사용자별 앨범은 수집 권한을 적용하며, 특정 사용자가 3장 모두 수집했는지는 조회하지 않았다.

## 적용한 저장 경로

- 검수 최종 미리보기 SVG를 1080×936 투명 PNG로 캡처한다. 개별 머리와 소품도 이미지에 포함된다.
- 서버는 PNG를 검사하고 원본 바이트 그대로 비공개 Storage에 업로드한다.
- 승인·이미지 참조·디자인 버전·감사 기록을 같은 트랜잭션에서 저장한다. 이미지 누락·업로드 실패·버전 충돌 때는 승인이 완료되지 않는다.
- 앱 API는 저장된 이미지 URL을 집의 `pets`·`dailyPets`·`ownerBonusPet`, 공유·내 강아지·앨범에 전달한다.
- 검수 목록에는 저장 이미지가 우선 표시된다. 과거 승인견은 **확정 이미지 저장**에서 현재 그림을 확인한 뒤 명시적으로 저장한다.

## 배포 및 검증 범위

- 운영 DB에 `20260906000100_reviewed_artwork_snapshots` 적용 완료.
- 운영 `pet-api` 버전 24 ACTIVE 확인. 운영 소스를 내려받아 이미지 전달 변경만 적용했다.
- AIT 앱을 새로 배포하지 않았다. 기존 앱의 `illustrationUrl` 표시 경로를 사용한다. 저장 이미지에 별도 혀를 덧그리지 않는 처리와 이미지 비율 처리는 로컬 `PetArtwork.tsx`에 준비되어 있으며 다음 AIT 빌드에 포함해야 한다.
- 타입 검사 및 관련 테스트 46개 통과. 실제 브라우저의 모의 승인에서 설기 선글라스·검정 나비넥타이가 PNG에 포함되고 1080×936 이미지로 로드됨을 확인했다. 모의 승인은 운영 DB/API에 저장 요청을 보내지 않았다.
- 실제 승인 저장 후 운영 앱까지의 최종 확인은 아직 하지 않았다. 과거 승인견이나 대기견의 그림을 임의로 확정해 검증하지 않는다.
