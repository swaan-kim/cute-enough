# 강아지 사진 1~5장 등록

> 과거 구현·배포 기록입니다. 당시 상태·명령은 현재 운영 절차가 아닙니다. [문서 안내](../README.md)에서 현재 가이드를 확인하세요. 도감 초기화·승인·출시는 별도의 명시적 확인 없이 실행하지 않습니다.

## 사용자 흐름

- 한 강아지에 사진 1~5장. 이름은 1~4자 필수이며, 첫 사진이 대표 사진입니다.
- 사진을 추가·삭제해도 이름과 꾸민 외형은 유지합니다. 사진마다 기기에서 JPEG 압축·EXIF 제거를 순차 실행합니다.
- 처리에 실패한 사진은 개별 재시도/삭제할 수 있습니다. 준비되지 않은 사진이 하나라도 있으면 등록을 막습니다.
- 안내: “운영자가 귀여움을 꼼꼼히 확인한 뒤, 친구들에게 한 장씩 보여드려요 🐾”
- 실제 점수나 AI 자동 판정은 없습니다. 운영자가 전체 사진과 최종 SVG를 확인한 뒤 명시적으로 승인합니다.
- 등록은 한 번, 강아지도 한 마리, 업로드 보너스도 한 번입니다. 기존 하루 등록 제한은 유지합니다.

## 전송·저장

신규 클라이언트의 `submitPet({dataUris})`는 `submitPhoto`를 사진마다 순차 호출한 뒤 `submit({photoReceipts})`로 등록을 확정합니다. 5장이면 정상 경로는 사진 전송 5회 + 등록 확정 1회입니다. 편집 중에는 서버를 호출하지 않습니다.

- `submitPhoto`: 익명키 확인 → JPEG 안전 처리 → 비공개 Storage 업로드 → 사용자·등록 ID·사진 순서에 묶인 서명 영수증 반환.
- `submit`: 영수증 검증 → 원본 존재 확인 → RPC에서 사진 목록·강아지·등록 보상을 하나의 트랜잭션으로 기록.
- 재시도는 동일 `submissionId`를 사용합니다. 성공한 사진 단계의 영수증은 최대 1시간 메모리에서만 재사용하며, 확정 완료 시 지웁니다. 실사나 영수증을 운영 브라우저 영구 저장소에 저장하지 않습니다.
- 예전 앱의 `dataUri` 한 장 등록은 호환합니다. 다중 `dataUris`를 서버 한 요청에서 처리하지 않습니다.
- 승인 전 실제 사진은 소유자에게만 제공하며, 타인 공유에는 캐릭터만 표시합니다. 승인 이후에는 기존 하루 한 장 수집 정책을 그대로 사용합니다.
- 기존 사진·승인·컬렉션·하트·감사 기록을 삭제하거나 초기화하지 않습니다.

## 검수

검수 페이지에 전체 사진 수와 썸네일이 표시됩니다. 큰 사진을 모두 확인하기 전에는 승인 버튼이 비활성화됩니다. URL 발급 실패 사진도 원래 사진 수에 포함하여, 일부 사진만 보인 상태에서 묶음 승인되지 않게 합니다. 승인 단위는 강아지 등록 한 건입니다. 기존 검수의 사진 관리 기능(순서·문구·제외·복구)과 구분하며, 이 등록 구현에서는 운영 사진이나 승인 상태를 변경하지 않습니다.

## 분할 전송 이유

Supabase는 Edge Function 요청당 CPU 2초·메모리 256MB 제한을 안내합니다. [공식 실행 제한](https://supabase.com/docs/guides/functions/limits)

로컬 Node 24에서 기존 `jpeg-js` 보안 정규화로 1024×1024 고복잡도 사진 5장을 처리했을 때 CPU 약 2.19~2.34초가 측정되어, 한 요청에서 5장을 처리하는 방식을 제외했습니다. 이 측정은 호스팅 성능 보장이 아니며, 실제 QR 5장 등록 검증이 추가로 필요합니다. 보안 정규화를 생략하거나 사진 해상도를 임의로 낮추지 않았습니다.

## 배포 경계

1. `20260906000400_multi_photo_submissions.sql` 다중 사진 RPC 마이그레이션 적용. 운영에 더 늦은 번호가 적용돼 있으면 누락 버전만 확인해 적용하고, 이력이나 기존 마이그레이션을 재작성하지 않습니다.
2. `submitPhoto`·영수증 기반 등록 API 배포.
3. 로컬 검수 서버 재시작 후 전체 사진 확인.
4. 새 AIT 생성·업로드 및 Toss QR에서 1장/5장/취소/중간 실패/동일 요청 재시도 확인.
5. 운영자가 테스트 대상을 명시 확인한 뒤 승인하여 소유자·타 사용자 흐름 검증.

소스 구현·로컬 테스트는 원격 DB 적용, API 배포, AIT 업로드 또는 개별 강아지 승인 완료를 뜻하지 않습니다. 선행 서버 배포 없이 새 AIT를 먼저 올리지 마세요.

실패 중 남은 Storage 파일을 즉시 일괄 삭제하지 마세요. DB 연결 여부를 확인하고, 영수증 만료·재시도 여유 기간이 지난 미연결 시도 파일만 운영 절차로 정리해야 합니다.
