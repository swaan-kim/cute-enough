## 바뀐 점

36번 이후 요청은 광고 확인 문구를 줄이는 것이 아니라 **간식을 주는 행동에서 광고를 바로 여는 것**이다. 티켓이 없고 새 사진을 만날 수 있을 때만 적용한다.

`강아지 선택 → 간식 선택 → 주기(버튼·강아지 터치·드롭) → 광고 → 고른 간식 먹기 → 쓰다듬기 → 사진`

- 강아지나 간식을 고르기만 하면 광고를 열지 않는다.
- 일반 확인 모달을 없앴다. 간식 화면에 `티켓 0장 · 간식을 주면 광고가 열려요.`와 `광고 보고 간식 주기`를 미리 표시한다.
- 이미 준비된 광고를 재사용한다. 준비 중이라도 간식을 다시 누를 필요 없이 준비가 끝나면 이어서 표시한다.
- `userEarnedReward`와 서버 보상을 확인하고 광고에서 돌아온 뒤에만 고른 간식을 먹는다. 사진 공개·티켓 차감 시점과 쓰다듬기 흐름은 그대로다.
- 취소·준비 실패·표시 실패에는 고른 간식을 유지하고 같은 행동으로 재시도한다. 일반 확인창을 다시 열지 않는다.
- SDK가 광고 시작·닫힘을 알려주지 않는 예외에서만 기존 수동 복귀 확인을 유지한다. 타이머만으로 보상을 주거나 다음 광고를 열지 않는다.

## 권한·공유·취소 안전장치

공유 보상 버튼은 사라진 모달 대신 간식 화면의 작은 대안 버튼으로 옮겼다. 공유 화면을 연 동안 간식과 광고의 중복 시작을 막는다. 공유 티켓을 받은 뒤에는 광고 안내 대신 일반 간식 안내로 바꾸고, 다음 간식 행동에서 서버가 확인한 티켓을 사용한다.

대기 중 무료·보너스 티켓이나 소유자·재열람 권한이 생기면 현재 서버 응답을 다시 검사하여 불필요한 광고를 건너뛴다. 광고 준비 전의 강아지 객체만 믿지 않고 최신 선택 상태와 진행 중 요청의 참조를 확인한다.

광고를 준비하는 개별 대기는 취소할 수 있지만 공용 광고 캐시는 유지한다. 화면 이탈 시 광고 작업 토큰의 소유권을 즉시 해제하여 이전 비동기 요청이 새 사진·공유 작업의 로딩 상태를 해제하지 못하게 한다. 서버에 이미 전달한 요청은 기존 요청 ID로 회수·정리한다. 사용자·티켓·도감·승인 기록과 운영 스위치는 이번 변경에서 수정하지 않는다.
