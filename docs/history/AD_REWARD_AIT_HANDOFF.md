2026-09-05 기준. 이 문서의 범위는 다른 창에서 수정 중인 앨범·화면 작업과 이미 구현된 보상 기능을 합쳐 동일 AIT 후보를 만드는 것이다. 기존 저장소와 미커밋 변경을 보존하고 완료된 보상 기능을 다시 만들지 않는다.

현재 프런트에는 별도의 공유 `VITE_` 활성화 스위치가 없다. 서버 capabilities와 SDK 지원 여부를 따른다. 서버 서비스 키, mTLS 인증서·개인 키, 알림 암호화 키·cron secret을 AIT·클라이언트·`VITE_`·Git에 넣지 않는다. 비밀 env 파일 내용은 출력하지 않는다.

공유 리워드 MCP에는 생성·수정 기능이 없다. 사용자가 콘솔에서 **workspace/appName, moduleId, 활성 상태, 보상 단위 `강아지 티켓`, 친구당 수량 `1`, 운영 기간**을 확인해 전달해야 한다. 현재 UUID가 실제 모듈 ID인지 확인되기 전 다른 ID를 추정하거나 보상 기능을 켜지 않는다.

알림의 새 서버/기능성 템플릿은 `APPROVED`, groupNo `11801`, materialNo `13665`, pushTemplateNo `99675`, 링크 `intoss://cute-enough`다. 조건형 동의문은 termsId `120468`, subscription `7898`이며, **동의문에 남은 이전 명칭을 `티켓`으로 수정해야 한다.** 현재 동의 조건 문구는 `무료 이용권이 충전되면 알려드릴까요?`다. MCP에는 동의문 조회·생성만 있어 기존 동의문 수정은 콘솔 화면에서 확인해야 한다. subscription·termsId는 SDK templateCode 대체 값이 아니다.

이전 승인 템플릿 `cute-enough-ticket-recharged`(groupNo `11799`)는 승인 후 수정이 거절되어 이력으로 남긴다. 새 템플릿을 사용하며 이전 코드로 발송하지 않는다. 서버 암호화 키·cron secret·Vault 연결·worker URL은 준비했고, 인증한 worker 조회는 HTTP 200과 `enabled: false`를 반환했다. 광고·공유·알림 운영 스위치는 모두 꺼져 있다. **동의문 명칭 수정과 QR 동의·수신 검증은 미완료이며 실제 푸시·친구 초대는 보내지 않았다.** 일반 광고성 푸시는 기능성 템플릿에 섞지 않으며 MCP 생성 대상이 아니므로 콘솔 웹에서 별도로 준비한다.

## 화면·앨범 변경에서도 유지할 동작

### 티켓과 사진 접근

- 사용자에게 보이는 명칭은 모두 **티켓**으로 통일한다. `무료 티켓`, `보너스 티켓`, `티켓 충전`을 사용하며 호환성을 위한 API·DB 식별자는 유지할 수 있다.
- KST 하루 공개 **4마리** 고정 + 내 최신 `pending | approved` 1마리. 내 강아지는 공개 진행도·티켓·광고에서 제외한다.
- 무료 티켓 최대 2장, 사용 후 3시간마다 1장 충전. KST 자정에는 공개 구성만 바뀌고 티켓은 초기화하지 않는다.
- 접근 순서는 **내 강아지/유효 재열람 → 해당 강아지의 미사용 광고 보상 → 무료 티켓 → 공유 보너스 티켓 → 새 광고**다.
- 보너스 티켓은 무료 티켓 2장과 별도 보관하며 자정·재실행으로 소멸하지 않는다. 광고·공유는 자연 충전 시각을 바꾸지 않는다.
- 홈에는 `무료 티켓 N/2 · 보너스 티켓 N장`, 공개 진행도는 `/4`로 표시한다. 앨범·즐겨찾기에서 사진을 열 때도 기존 접근권 검증과 같은 API 계약을 유지한다.
- 최초 사진 접근 재시도는 원래 방식과 같은 `reveal.requestId`를 유지한다. URL만 만료되면 유효 접근권으로 URL을 갱신하고 티켓을 다시 차감하지 않는다. 접근권까지 만료되면 자동 차감 없이 새 방문 흐름으로 안내한다.
- `apiVersion: 2`, 서버 `serverNow`·잔액·오류 응답의 상태 보정을 유지한다. 로컬 잔액만으로 운영 접근권을 발급하지 않는다.

### 광고

- 무료와 공유 보너스가 **모두 0일 때만** 새 광고를 시작한다. 하루 최대 2회는 사진 공개 수가 아닌 **광고 완료 수**다. 취소·재생 실패는 보상·한도를 차감하지 않는다.
- 광고 전에 서버 세션을 생성한다. `userEarnedReward` 직후 복구 기록을 저장하고 서버 완료 요청을 보낸다. 광고 창 닫힘까지 보상 기록을 미루지 않는다.
- 광고 중 자연 충전이 발생해도 광고 보상을 보존하고 자연 충전 티켓도 남긴다. 서버 응답 유실·앱 종료 후 재실행에서 같은 세션을 복구한다.
- 미완료로 남은 세션의 정리·재진입을 유지한다. 운영 중단 후에도 이미 지급된 광고 접근권을 없애지 않는다.

### 친구 초대

- SDK 3.1.1의 `Promotion.openContactsInvite({ options: { moduleId }, onEvent, onError })`를 유지한다.
- 버튼 `친구에게 공유하고 티켓 받기`, 설명 `친구 1명에게 초대하면 보너스 티켓 1장을 받아요.`를 사용한다. 무료 만충·오늘 공개견 완료 상태에서도 적립할 수 있다.
- 초대 화면 전에 서버 세션을 만든다. `sendViral`마다 수량·단위·eventSequence와 요청 ID를 복구 저장소에 기록하고 지급 요청한다. 실제 여러 친구의 수량을 반영하며 화면 진입당 1장 또는 발신자 하루 1장으로 제한하지 않는다.
- `close`만으로 지급하지 않는다. 종료 집계와 수신 보상 기록이 어긋나면 확인 상태로 남기고 추가 지급하지 않는다. 중단된 세션도 종료/복구하여 다음 진입을 막지 않는다.
- 개별 강아지 일반 공유·링크 복사·취소는 보상을 지급하지 않는다. pending 공유에서 타인은 실사 사진을 받지 못한다.
- SDK 콜백에는 친구 ID·고유 지급 ID·검증 서명이 없다. 도착한 요청의 중복 처리는 막되, 콜백 도착 전 종료까지 완전 복구했다고 안내하지 않는다.

### 충전 알림

- 사용자가 `충전되면 알려주세요`를 눌렀을 때만 서버가 준 templateCode로 `requestNotificationAgreement`를 호출한다. 앱 시작 시 자동 동의 요청하지 않는다.
- `newAgreement | alreadyAgreed`일 때만 서버 신청, 거절·오류·미지원 때는 신청하지 않는다. 해제와 기존 신청 상태 조회도 유지한다.
- 서버 담당 범위: 자연 무료 0→1, KST 하루 최대 1회, 21:00~08:00 보류, 발송 전 동의·방문·잔액·오늘 완료 재확인. 광고·공유 보상은 충전 알림 원인이 아니다.
- 새 템플릿에 저장된 제목은 `티켓 충전`, 본문은 `강아지 티켓이 충전됐어요. (옆집 강아지 알림)`이다. 동의문에도 같은 명칭을 적용한 뒤 실제 동의·수신 화면에서 확인한다. 신규 사용자 대상 일반 광고성 푸시는 이번 충전 알림에 섞지 않는다.

각 항목에 Android/iOS·Toss 버전·deploymentId·확인 시각과 `통과 / 실패 / 미실행`을 기록한다. 로컬·Vercel 결과를 Toss QR 통과로 바꾸지 않는다.

## 전달할 결과

1. 통합한 정확한 Git commit 및 남은 미커밋 변경, 실행한 검사 결과와 실패/미실행 항목.
2. AIT 절대 경로, SHA-256, bytes, deploymentId, runtime, 광고 빌드 플래그·슬롯 ID. 서버 광고·공유·알림 스위치는 별도 값과 확인 시각으로 기록한다.
3. `파일 생성 / 콘솔 업로드 / QR 생성 / 실기기 검증 / 심사 요청 / 출시` 상태를 각각 구분한다. 다른 파일로 재빌드하면 새 후보로 기록하고 QR 대상도 다시 맞춘다.
미리보기·썸네일은 사용자가 별도로 진행하므로 이 작업의 제작·캡처 산출물에서 제외한다. 기능 검증용 QR 확인은 계속 수행한다.

운영 절차는 [배포 기록](REWARD_RELEASE_20260905.md), 알림 상세는 [충전 알림 운영](../operations/RECHARGE_NOTIFICATIONS.md)을 따른다. 각 창은 담당 파일을 독립적으로 작업하며, 사용자의 별도 요청 없이 다른 창에 대화 내용이나 진행 상황을 전달하지 않는다. 최종 설정은 실제 콘솔·서버 조회 및 후보 기록으로 확인한다.
