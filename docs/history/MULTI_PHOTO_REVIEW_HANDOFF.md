> 과거 구현·배포 기록입니다. 당시 상태·명령은 현재 운영 절차가 아닙니다. [문서 안내](../README.md)에서 현재 가이드를 확인하세요. 도감 초기화·승인·출시는 별도의 명시적 확인 없이 실행하지 않습니다.

## 사용자 등록과 제작자 검수

등록창은 현재 구현 중인 **1~5장** 선택·추가·제외·순서 결정 흐름을 사용한다. 첫 사진이 대표사진이다. 소품 선택지는 늘리지 않는다. 등록 재시도는 같은 submissionId로 원래 사진 묶음을 반환하며 중복 등록·사진 덧붙이기를 하지 않는다.

검수창은 한 장씩 크게 보는 갤러리와 좌우 버튼·작은 썸네일을 사용한다. 대기견과 기존 승인견 모두 **사진 관리**에서 순서, 30자 문구, 제외·복구를 편집한다. SVG 보정 화면에서도 등록 원본 전체를 넘겨볼 수 있다. 사용자 등록 소스는 이 검수 작업에서 수정하지 않는다.

편집 내용은 저장 전까지 화면에만 있다. **사진 변경 저장**을 누르면 사진 목록에만 적용되며 승인 상태나 공개 SVG는 바뀌지 않는다. 승인견은 저장한 사진 순서·문구·포함 여부가 앱의 다음 사진 조회부터 반영된다. 저장하지 않은 사진 수정 상태로 승인하지 않도록 편집 모달을 먼저 저장하거나 변경을 버리고 닫는다.

## 사진 데이터 규격

- `pet_photos.id`는 사진 고유 식별자다. 순서 변경·문구 변경으로 새 ID를 만들거나 기존 ID에 다른 파일을 덮어쓰지 않는다.
- `storage_path`는 원본 경로로 유지한다. `sort_order`는 포함된 사진의 0부터 시작하는 순서이며 첫 사진을 `pets.storage_path`와 동기화한다.
- `caption`은 null 또는 30 Unicode 문자 이내의 일반 한 줄 문구다. HTML·제어·숨김 방향 문자는 허용하지 않는다. 기존 앱의 사진별 `photoCaption`과 앨범 응답에 연결된다.
- 제외한 사진은 `is_active=false`, `sort_order=null`로 보관한다. 원본 Storage, 사진 ID, 문구, 수집 권리와 감사 기록을 삭제하지 않는다. 복구하면 동일 ID가 다시 포함된다.
- 제외된 사진은 앱·앨범의 활성 사진 조회에서 숨겨진다. 복구 시 기존 보유 권리가 다시 적용된다.
- 최소 1장을 유지한다. 신규 등록 상한은 5장, 검수 저장은 기존 DB의 선별 사진 최대 16장까지 보존한다.

## 제작자 API

`GET /api/review-photos?petId=<uuid>`

```ts
type ReviewPhotoSet = {
  petId: string;
  revision: string; // 서버가 발급한 사진 목록의 SHA-256, URL 만료와 무관
  photos: Array<{
    photoId: string;
    url: string | null; // 로컬 불투명 프록시 주소
    caption: string | null;
    sortOrder: number | null;
    isActive: boolean;
    available: boolean;
  }>;
};
```

`POST /api/review-photos`는 `{ petId, expectedRevision, photos: [{ photoId, caption }] }`를 받는다. 배열의 순서가 확정 순서이며 빠진 사진은 제외된다. 알려진 제외 사진 ID를 다시 넣어 복구할 수 있다. 일반 사용자 등록 API에 이 제작자 API를 노출하지 않는다.

서버는 `save_pet_photo_review` RPC에서 사진 소속·원본 존재·문구·순서·최신 revision을 검증하고, 원본 ID를 유지하며 저장과 사진 감사 기록을 한 트랜잭션으로 처리한다. 저장 후 DB를 다시 읽어 revision과 요청 순서·문구를 확인한다. 충돌은 `REVIEW_PHOTOS_CHANGED`; 화면 수정 내용을 유지하고 최신 목록을 다시 불러오게 한다.

## 배포 경계

- 등록 작업: `20260906000400_multi_photo_submissions.sql`, 사용자 등록 UI/API 담당.
- 검수 작업: `20260906000500_review_pet_photos.sql`, 검수 서버/API/UI 담당. 먼저 로컬 DB 테스트와 저장 권한·정체성 보존 검증 후 적용한다.
- 검수 서버는 schema 미적용 시 `REVIEW_PHOTOS_SETUP_REQUIRED`를 반환하며, 기존 사진은 읽기 전용으로 볼 수 있다. 저장 성공처럼 표시하지 않는다.
- 이 검수 기능을 추가하는 것과 실제 운영 사진을 편집·제외하거나 강아지를 승인하는 것은 별개다. 실제 사진 변경은 제작자의 저장 버튼으로만 수행한다.

## 직접 검증

2026-09-06 운영 DB에 검수용 `005` 마이그레이션을 적용하고 로컬 검수 서버를 재시작했다. 같은 트랜잭션에서 기존 강아지·사진·Storage·수집권·공개 SVG 데이터 해시 불변을 검증했다. 사진 18장, 수집권 102건은 보존됐고 실제 사진 변경 감사 건수는 0건이다. 등록용 `004` 배포는 등록 작업의 별도 범위다.
