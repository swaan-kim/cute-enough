## 작업 시작 시 운영/로컬 차이

- 운영 승인 7건, 대기 6건, 반려 2건을 읽기 전용으로 확인했다. 대기견은 별도 창에서 운영자가 수정할 예정이며 이 배포에서 수정하거나 승인하지 않는다.
- 운영 DB는 공개 5마리 상태였고 공유/광고 보상 원장과 알림 테이블은 아직 없었다. 로컬 목표는 공개 4마리 + 내 최신 pending/approved 1마리다.
- 정확 일치 검수 SQL은 운영에 수동 적용됐지만 마이그레이션 이력에는 없었다. 이력만 보고 SQL을 중복 적용하지 않는다.
- 과거 `20260829000100_fix_wooyoo_white_traits.sql`처럼 개별 강아지를 바꾸는 SQL은 자동 재실행하지 않는다.
- 기존 전체 업로드 이력 변경과 새 보상 API는 Edge Function 재배포 전까지 운영에 반영되지 않는다.
- Supabase CLI 재로그인과 프로젝트 연결은 완료했다. 인증 성공은 마이그레이션·함수 배포 성공과 별개다.

## 콘솔 확인과 알려진 제한

1. **공유 모듈 확인 필요.** `e5de3e72-cbfb-4b50-a050-9fd71fb4368b`가 해당 앱 소속이며 보상 단위 `강아지 티켓`, 친구당 수량 `1`인지 확인한다. 마지막 공유 설정 조회는 `Auth required`였고, 재인증 뒤 콘솔 조회 연결을 다시 확인해야 한다.
2. **실제 공유 이벤트 검증 필요.** 공개 SDK에는 친구 ID·고유 지급 ID·검증 서명이 없고 서버 발송 이력 API를 확인하지 못했다. 수신한 콜백의 서버 요청 중복은 막지만 콜백 수신 전 앱 종료까지 완전 복구를 약속하지 않는다. 실제 친구에게 임의로 초대를 보내지 않는다.
3. **알림 캠페인 준비 필요.** 마지막 콘솔 조회에서 동의문·템플릿은 없었다. 동의문과 기능성 캠페인 승인, 서버 secrets/Vault 연결, 지정 테스트 수신자의 실제 QR 검증 전까지 알림 스위치를 꺼 둔다.
4. **실기기 테스트 필요.** Vercel과 로컬 브라우저 테스트를 Toss QR A/B·광고·초대·알림 성공으로 간주하지 않는다. 대기견 승인은 운영자가 별도로 진행한다.
5. **미리보기 교체 필요.** 최종 QR 실제 화면으로 636×1048 PNG 4장과 1932×828 PNG 썸네일을 만든다. 홈에는 무료/보너스 잔액을 반영한다. 완성 이미지·설명문을 확인한 뒤 앱정보 검토를 요청한다.
6. **초기 JS 후속 개선.** 구현 전 최신 로컬 초기 JS는 약 432KB gzip으로 목표 350KB를 넘었다. 최종 빌드 수치를 다시 기록하되 코드 분할은 보상 안정화 이후 진행한다.
