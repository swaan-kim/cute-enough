# 세 번째 교감에서 사진 요청 · 2026-09-13

이 기록은 [이전 사진 준비 방식](PHOTO_FLOW_RELEASE_20260913.md)의 클라이언트 동작을 대체한다. 별도 사전 요청 대신 기존 API를 마지막 입력 순간에 한 번 호출한다.

## 변경

- 간식·첫 두 입력: 사진 API 호출 없음. 첫 두 반응은 450ms 유지.
- 세 번째 유효 입력: 기존 `reveal` 또는 `ownerPhoto` 요청 시작. 기존 무료 재열람·티켓·요청 ID 정책 유지.
- 마지막 900ms: 작은 점프 한 번 후 안착, 빠른 꼬리 반응과 반달 눈웃음. 사진 요청·다운로드·디코딩을 이 시간과 겹친다.
- 900ms 뒤: 준비된 사진을 표시하거나 같은 창에서 로딩·재시도. 닫힌 화면은 늦은 응답으로 다시 열지 않는다.
- 눈 위치는 저장된 eye 역할의 실제 SVG 경계에서 측정한다. 측정 불가 시 원래 눈 유지. 저장 문서·SHA·디자인 버전은 변경하지 않는다.
- 움직임 줄이기에서는 점프·꼬리 애니메이션 없이 눈웃음과 하트를 표시한다.
- 클라이언트의 `photoPrepare`·선행 다운로드 경로 제거. 서버 호환 코드와 기존 마이그레이션은 보존하며 이번에 배포하지 않는다.

## 검증 결과

`npm run test:flows` 전체 통과:

| Vitest 단위·통합 | 102파일 / 1,070개 |
| 앱·E2E 타입 검사 | 통과 |
| 모바일 정상 App E2E | 360·390·430px, 33개 |
| 개발 StrictMode 첫 진입 | 1개 |

브라우저 시계를 제어해 899ms에는 반응이 남고 모달이 없으며, 900ms에 모달이 열리는지 확인했다. 첫 두 입력의 사진 호출 0회, 마지막 단일 요청, 내 사진·재열람 무차감, 광고 완료/취소/중복 이벤트, A/B 좋아요, 느린 다운로드와 이탈을 검사했다. 반달 눈웃음 캡처와 reduced-motion도 확인했다.

검사 작성 중 빈 테스트 묶음, 입력 후 이름이 바뀌는 버튼 선택자, Node/브라우저 시계 차이를 수정했다. 실행 중 소스 변경에 따른 새로고침 영향을 제외하도록 최종 소스를 고정한 뒤 전체를 다시 실행했다. 재시도로 실패를 숨기지 않았다.
